# emocar

A face on the car that reacts to how it moves. ESP32-C3 Super Mini + L3G4200D (GY-50) gyro
+ SH1106 1.3" OLED on one I²C bus (SDA GPIO8 / SCL GPIO9, see [wiring.md](wiring.md)).
A PC web UI (`server/`) picks a GIF for each state and sends it to the car over USB.

## How to run

Plug the car in over USB. The server opens http://localhost:8080 in your browser.

### Release build

Download from https://github.com/sangnnbs/emocar/releases and put the file in a folder of
its own: the server keeps your GIF library in `gifs/` next to it.

Windows x64: double-click `emocar-server_<ver>_windows_amd64.exe`. SmartScreen warns
because it is unsigned: **More info → Run anyway**. Close the console window to stop it.

Linux x64 / ARM64 (Ctrl+C stops it):

```text
chmod +x emocar-server_<ver>_linux_amd64
./emocar-server_<ver>_linux_amd64
```

Once per Linux PC, so the server can open the USB port (log out and back in after):

```text
sudo usermod -aG dialout $USER
```

macOS has no release build yet; build it on the Mac:

```text
cd server && go build
```

### With make

```text
cd server
make run      # build + start, browser opens
make down     # stop it (needed before flashing the car)
make          # list all targets
```

`-open=false` stops the browser from opening. Other flags and the UI: [server/README.md](server/README.md).

## Files

```text
emocar/
├── emocar.ino    bring-up + main loop (gyro FIFO → motion → anim → cmd)
├── config.h      every pin / address / rate / threshold (defaults; /configs tunes them live)
├── gyro.*        L3G4200D driver, FIFO stream mode
├── motion.*      bias, vibration RMS, state machine
├── cfg.*         live state settings, saved on the car in /cfg.bin
├── display.*     panel driver; profile (DISP_*) must match server/profiles.json
├── anim.*        .qgif player: LittleFS slot file per state, PROGMEM fallback
├── cmd.*         USB serial command protocol (uploads, CFG, TELEM)
├── telem.*       sensor stream for the server's /dashboard
├── anim_data.h   GENERATED by mkanim.py: placeholder faces
├── test/         host tests for motion.*
├── server/       Go web server on the PC
├── gifs/ downloads/ emoji_lib/   GIF library for the server, never flashed
├── wiring.md     GY-50 + SH1106 ↔ C3 Super Mini
├── DESIGN.md     why the code is the way it is, measurements, tests
└── PLANS.md      roadmap
```

## Build / flash

Stop the server first: it holds the USB port.

From source (Arduino IDE: board **ESP32C3 Dev Module**, **USB CDC On Boot: Enabled**,
library **U8g2**):

```text
cd ~/sang/esp32
arduino-cli compile --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc emocar
arduino-cli upload  --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc -p /dev/ttyACM0 emocar
```

From a release `.bin`:

- `emocar-firmware_<ver>_esp32c3_app.bin` at `0x10000` updates a car and keeps its GIFs
  and /configs values.
- `emocar-firmware_<ver>_esp32c3_full.bin` at `0x0` is for a blank board. It covers the
  whole 4 MB, so it wipes them.

```text
esptool --chip esp32c3 -p /dev/ttyACM0 write_flash 0x10000 emocar-firmware_<ver>_esp32c3_app.bin
```

No install: https://espressif.github.io/esptool-js/ in Chrome/Edge → Connect → file + offset
→ Program. On Windows the port is `COM5`-style.

## States

| State | Face | When |
|---|---|---|
| NORMAL | 🙂 | default |
| FAST | 😮 | sustained vibration on a surface (`FAST_ENTER_RMS`, `FAST_HOLD_MS`) |
| DIZZY | 🥴 | shaken hard on any axis, or spun one way for 5 s; lasts 2 s after |
| HAPPY | 🥰 | held in a hand (roll travel a car on wheels can't make) |

Priority DIZZY > HAPPY > FAST > NORMAL. Each state but NORMAL can be switched off.
`config.h` holds the defaults; the server's `/configs` page changes them on the running
car and **Export** writes them back into `config.h`. Details in [DESIGN.md](DESIGN.md).
